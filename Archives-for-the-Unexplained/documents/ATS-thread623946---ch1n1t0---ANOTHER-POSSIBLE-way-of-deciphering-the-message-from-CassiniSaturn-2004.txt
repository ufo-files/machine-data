Anyone can try and see for yourselves how the image of the spectrogram is produced using
this file - www.sendspace.com... . It is a zip archive that you load into FL Studio 9.0
(or higher), demo version works perfectly, too. You have two instances of the same audio
file present there (original), and the second one, again original, but has been pitched for
you. To check how that's done you need to click on the channel Cassini Pitched in the
sequencer window, under channel settings box look for the tab labelled "MISC", click on it,
and notice that the center frequency, represented by an orange rectangle above the
'piano' keys, is set to C3. As the default center frequency of every channel you set in FL
Studio is C5, this shows you that the second instance was pitched up two octaves (the note
that's triggering the instance is always C5, but if you move the center frequency in the
MISC tab to C3, this means that when C5 plays, it will actually be C7, thus pitching the
MISC tab to C3, this means that when C5 plays, it will actually be C7, thus pitching the
signal up).

It's important to say here that there are different algorithms that can pitch sound. The
one I've been using simply does the following - it speeds up the sound, thus pitching it up.
There are pitch shift techniques that involve preserving the length and speed of the file,
with altering only the pitch, as well as the other way around. These are not used here.

The file is sped up, thus stretching the frequencies from the original file towards the
higher spectrum regions. This is as if you would take a spectrogram image of the original
sound file, stretch that image horizontally (taking the frequency details that were
originally in the most left side and squeezing them to the right) and in the mean time -
scaling the image down vertically.

What I can advise is to use any digital audio workstation that has the ability to do this in
realtime, without the processing being applied to the waveform and some of the original
data being altered, or gone and lost. Most good such software have demos on the net, so
you are free to give it a try for yourselves. And I also advise you to use FL in this
particular case, because I've provided with a ZIP file one only has to open in an instance.

November 04, 2010

Engineers at NASA's Jet Propulsion Laboratory, Pasadena, Calif., are working to
understand what caused NASA's Cassini spacecraft to put itself into "safe mode," a
precautionary standby mode. Cassini entered safe mode around 4 p.m. PDT (7 p.m. EDT)
on Tuesday, Nov. 2.

Since going into safe mode, the spacecraft has performed as expected, suspending the
flow of science data and sending back only data about engineering and spacecraft health.
Cassini is programmed to put itself into safe mode automatically any time it detects a
condition on the spacecraft that requires action from mission controllers on the ground.

Engineers say it is not likely that Cassini will be able to resume full operations before a
planned Nov. 11 flyby of Saturn's moon Titan. But Cassini has 53 more Titan flybys planned
in its extended mission, which lasts until 2017.

"The spacecraft responded exactly as it should have, and I fully expect that we will get
Cassini back up and running with no problems," said Bob Mitchell, Cassini program
manager based at JPL. "Over the more than six years we have been at Saturn, this is only
the second safing event. So considering the complexity of demands we have made on
Cassini, the spacecraft has performed exceptionally well for us."

Since Cassini launched in 1997, Cassini has put itself into safe mode a total of six times.

The Cassini-Huygens mission is a cooperative project of NASA, the European Space Agency
and the Italian Space Agency. The Jet Propulsion Laboratory, a division of the California
Institute of Technology in Pasadena, manages the mission for NASA's Science Mission
Directorate, Washington.
